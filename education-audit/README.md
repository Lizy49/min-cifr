# Контроль сайтов образования Магаданской области

Веб-приложение на Python с MySQL для мониторинга школ, детских садов, колледжей и техникумов. Интерфейс выполнен по предоставленному скриншоту 49gov.ru. Код одинаковый для Windows и Linux; браузер служит интерфейсом.

## Быстрый запуск через Docker на Windows или Linux

Нужны Docker Engine с Compose (Linux) или Docker Desktop с Linux-контейнерами (Windows). Для генерации `.env` нужен Python 3.11+; для самого приложения в Docker локальный Python не используется.

В папке проекта выполните:

```text
python configure.py
docker compose up --build -d
```

На Linux первая команда обычно `python3 configure.py`. Откройте http://127.0.0.1:8000. Первая инициализация MySQL занимает некоторое время. Проверка состояния: `docker compose ps`; журналы: `docker compose logs --tail=100 app`; остановка: `docker compose down`.

Данные сохраняются в Docker volume `mysql_data`. Не используйте `docker compose down -v`, если хотите сохранить результаты. Пароли `.env` используются при **первом** создании базы; изменение файла не меняет пароль уже существующей MySQL.

## Запуск без Docker с установленной MySQL

Нужны Python 3.11+ и MySQL 8.0/8.4. Python 3.12 рекомендуется. Создайте окружение:

Windows PowerShell:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe configure.py
.venv/Scripts/python.exe init_mysql.py
.venv/Scripts/python.exe run.py --init-db
```

Linux:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python configure.py
.venv/bin/python init_mysql.py
.venv/bin/python run.py --init-db
```

На Debian/Ubuntu для `venv` может потребоваться системный пакет `python3-venv`. `init_mysql.py` запрашивает пароль администратора MySQL в терминале, создаёт базу и отдельного пользователя приложения. Он не меняет пароль существующей учётной записи. Если пользователь уже существует с другим паролем, согласуйте `DB_PASSWORD` в `.env`. На Linux с socket-аутентификацией root создайте базу и пользователя через вашу административную MySQL-сессию.

В `.env` задайте `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` для своей MySQL. `SECRET_KEY` оставьте случайным. `database/schema.sql` содержит схему для импорта через Workbench или mysql; создаёт только таблицы, не пользователей. `--init-db` тоже создаёт отсутствующие таблицы и добавляет реестр, сохраняя существующие записи.

Для ручного импорта реестра после схемы выполните `database/seed.sql`. Он содержит 87 учреждений без паролей и результатов тестирования. Автоматический запуск импортирует тот же список из JSON, поэтому выбирать нужно удобный вам способ.

После первой настройки доступны `start-windows.ps1` и `sh start-linux.sh`. Они создают окружение, устанавливают зависимости и запускают приложение; установленная и настроенная MySQL должна работать заранее. Дальнейший запуск вручную: `python run.py` из активированного окружения. Сервис использует Waitress, а не отладочный сервер Flask.

## Работа в приложении

1. Откройте «Учреждения», выберите сайты, нажмите «Проверить выбранные». Можно добавить свой публичный сайт.
2. В истории откройте запуск. Прогресс и окончание обновляются автоматически. В очереди выполняется одна проверка за раз.
3. В отчёте смотрите замечания, неопределённые результаты и доказательства: URL, фрагмент страницы, дата загрузки, HTTP-код, хеш.
4. При ручной сверке подтвердите находку или отметьте ложное срабатывание; комментарий сохранится в MySQL.
5. Скачайте CSV/JSON или нажмите «Печать / PDF» и выберите сохранение в PDF в браузере.
6. В карточке учреждения задайте период 24 часа / 7 дней и до 5 внешних источников для фактчекинга.
7. После проверок сравните учреждения и выберите эталон. СПО сравнивается отдельно от школ и детских садов.

Запуски по расписанию работают только пока включён процесс приложения. Очередь переживает перезапуск. Прерванный активный запуск спустя 20 минут без обновления помечается сбоем. Один экземпляр приложения с одним встроенным рабочим процессом рассчитан на локальную демонстрацию и небольшую установку.

## Подключение ИИ

Без модели уже работают краулер, правила, база, история, сравнение и отчёты. ИИ **не включён по умолчанию**: интерфейс сообщает об этом, вымышленные ответы не подставляются.

### GigaChat без установки модели

Облачный GigaChat выбран в новой конфигурации по умолчанию; без ключа приложение показывает «ключ не задан». Ollama для этого варианта не нужен.

1. Откройте https://developers.sber.ru/docs/ru/gigachat/quickstart/ind-create-project и создайте проект GigaChat API в кабинете Studio через Сбер ID. Проверьте условия Freemium и баланс именно вашего проекта: наличие бесплатного доступа для нового аккаунта заранее не гарантируется.
2. Получите **Authorization key / ключ авторизации**. Не используйте отдельный Client Secret или временный access_token.
3. В окружении приложения выполните `python configure_gigachat.py`. Ключ вводится скрыто, сохраняется только в `.env` и не выводится в консоль. Альтернатива — вручную заполнить `.env`:

```dotenv
AI_PROVIDER=gigachat
GIGACHAT_CREDENTIALS=ваш_ключ_авторизации
GIGACHAT_MODEL=GigaChat
GIGACHAT_SCOPE=GIGACHAT_API_PERS
```

4. Перезапустите приложение. При Docker: `docker compose up -d --force-recreate app`, чтобы контейнер получил обновлённые переменные.
5. Откройте **«Подключение ИИ»** (`/ai`) и нажмите **«Проверить соединение с GigaChat»**. Проверка запрашивает список моделей без передачи текстов сайтов и без генерации. Успешная проверка авторизации не доказывает наличие токенов для генерации.
6. Запустите новую проверку учреждения. Результат обращения к модели виден в разделе «ИИ-анализ»; старые отчёты автоматически не изменяются.

Авторизация: Basic Authorization key → временный Bearer token, обновляемый автоматически. Адрес модели — `https://api.giga.chat/v1`, OAuth — `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`. Scope должен соответствовать вашему проекту; для физлиц обычно `GIGACHAT_API_PERS`. При недоступности выбранной модели возьмите точное имя из списка, полученного проверкой, и задайте `GIGACHAT_MODEL`.

TLS всегда проверяется. Если окружение не доверяет сертификату API, задайте `GIGACHAT_CA_BUNDLE` — путь к доверенному PEM-файлу с нужной цепочкой CA. Относительный путь считается от папки проекта. Инструкция поставщика: https://developers.sber.ru/docs/ru/gigachat/certificates . Для Docker поместите PEM в папку проекта до сборки и используйте путь внутри контейнера. Отключать проверку сертификатов не требуется.

В облако передаются ограниченные фрагменты публичных страниц и внешних источников. Ключи не передаются в браузер, MySQL, JSON/CSV-отчёты и исходный архив. Подсказки ИИ не становятся автоматическими подтверждёнными нарушениями. Ограничения/ошибки доступа, квоты, сертификатов и формата отображаются без раскрытия токенов.

### Локальная альтернатива Ollama

Установите Ollama из официального источника, загрузите доступную вам модель с поддержкой русского языка и JSON-ответов. В `.env`:

```dotenv
AI_PROVIDER=ollama
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_MODEL=имя_установленной_модели
```

Перезапустите приложение. Имя модели должно совпадать с реально установленным. Размер модели выбирайте по памяти вашего компьютера. При Docker локальный Ollama доступен на Windows через `http://host.docker.internal:11434`; на Linux при необходимости добавьте в Compose `extra_hosts: ["host.docker.internal:host-gateway"]` и разрешите Ollama принимать соединения из Docker. Не выставляйте API модели в публичную сеть.

Модель получает ограниченные фрагменты страниц и внешних источников, предлагает сопоставления новостей/мероприятий, неполные сведения и гипотезы. Подсказки хранятся отдельно и требуют ручного подтверждения. Неудача модели не уничтожает результаты правил. Внешние страницы трактуются как недоверенные данные. При локальном Ollama платные API не требуются; стоимость и скорость зависят от оборудования. Конкретная модель не поставляется вместе с проектом.

## Реестр и источники

`data/organizations.json`: 40 школ и 40 детских садов из «Описание проблемы.docx», ещё 4 колледжа и 3 техникума из опубликованного списка СПО администрации Магадана: https://magadangorod.ru/common/upload/22/editor/file/42.pdf (сверка 07.11.2026). Этот список может содержать старые адреса, приложение честно отмечает недоступность. Полноту охвата всех действующих СПО региона нужно подтвердить у организаторов; филиалы и лицеи не добавлялись как отдельные колледжи.

Дополнительная сверка: https://monitoring.miccedu.ru/iam/2025/_spo/inst.php?id=104751. Обновить школы/сады из нового DOCX можно скриптом `python tools/import_docx.py "Описание проблемы.docx" data/schools-new.json`; перед импортом в основной реестр объедините списки. Источник сохраняется у каждой организации.

## Ограничения версии 1.0

- Статический HTML, без браузерного выполнения JavaScript; недоступный или нераспознанный раздел получает «Нужна проверка».
- Пределы по умолчанию: 60 ответов, 12 документов, 180 секунд обхода; они меняются через `.env`. На больших сайтах это выборка, а не полный архив.
- Новости: структурированные даты, интервал 14 дней; срок 24 часа подтверждается только при наличии точного времени события и публикации. Произвольные даты из текста не превращаются в факты.
- Кварталы определяются по `Asia/Magadan`; переход года учтён.
- Полнота карточек сотрудников, содержание программ, применимость документов и оформление фотографий требуют ручной/ИИ-сверки. Их наличие не выдаётся за соответствие всем требованиям.
- PDF читается до 30 страниц при наличии текстового слоя. OCR, разбор DOCX/XLSX, оценка качества фото не включены.
- Фактчекинг читает заданные внешние публикации; автоматического веб-поиска и окончательных решений о ложности новостей нет.
- Сравнение документов использует имена файлов: переименованный документ может попасть в кандидаты для ручной сверки. Эталон не заменяет нормативный перечень.
- Чек-лист колледжей и техникумов — расширение задания команды, не юридическая проверка по действующему законодательству.
- Авторизация и роли пользователей не реализованы. По умолчанию доступ только с этого компьютера; для сетевого внедрения нужны авторизация, HTTPS и сетевые ограничения. DNS проверяется до запросов и после перенаправлений, но это не замена изоляции исходящего трафика при публичной эксплуатации.

## База и код

Таблицы: `organizations` (реестр, расписание, внешние источники, эталон); `runs` (очередь и история); `pages` (источники и тексты); `results` (проверки, доказательства, решения специалиста). Связи — внешние ключи; русский текст — `utf8mb4`. Секреты находятся только в `.env`, не в исходниках.

`audit/crawler.py` — обход и извлечение; `rules.py` — проверки; `ai.py` — локальный ИИ; `worker.py` — очередь и расписание; `web.py` — интерфейс и экспорт; `models.py` — схема. Текущая версия создаёт таблицы автоматически, миграции при изменении схемы нужно добавлять отдельно.

Тесты:

```text
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Автотесты правил и HTTP-маршрутов используют временную SQLite исключительно как тестовый стенд. Рабочее приложение подключается к MySQL и не подменяет её SQLite. Проверки реальной MySQL и сайтов описаны в `VERIFICATION.md`.

Официальная документация выбранных компонентов: https://flask.palletsprojects.com/en/stable/deploying/waitress/ ; https://docs.sqlalchemy.org/en/20/dialects/mysql.html ; https://hub.docker.com/_/mysql ; https://github.com/ollama/ollama/blob/main/docs/api.md .
