# Gosweb Audit — настольное приложение

Отдельное настольное приложение для проверки сайтов школ и детских садов по техническому заданию хакатона Магаданской области.

## Возможности первой версии

- Реестр учреждений Магаданской области (школы и детские сады из исходного перечня).
- Ограниченный обход публичного сайта с уважением robots.txt.
- Проверки новостей, сроков публикации, мероприятий, обязательных разделов, документов, контактов и шаблонного текста.
- Отдельные статусы «Пройдено», «Замечание», «Проблема» и «Нужна ручная проверка».
- Ссылки и фрагменты страниц в качестве доказательств для каждого вывода.
- История запусков и локальная SQLite-база.
- Отчёт учреждения в HTML/CSV и сводка результатов последних проверок всего реестра.
- Выбор эталонного сайта отдельно для школы и детского сада; детерминированная сверка найденных документов и дополнительный ИИ-анализ различий структуры и наполнения по сохранённому отчёту эталона.
- Настройка до пяти внешних URL для фактчекинга.
- Необязательный анализ через DeepSeek API, Gemini, GigaChat или локальную модель Ollama: ИИ сопоставляет сайт с эталоном, результаты правил и внешние источники; ИИ-выводы не становятся нарушениями автоматически.
- Три режима обхода: быстрый, сбалансированный и глубокий.
- Панель показателей, локальная настройка ИИ из интерфейса и остановка очереди после текущего сайта.
- Интерфейс PyQt6, рассчитанный на Linux/Kubuntu.

## Запуск в Linux / Kubuntu

Нужен Python 3.11 или новее.

```bash
cd desktop-app
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python run.py
```

Проверить весь реестр без открытия окна можно командой `python run.py --run-all`. Для отдельного типа используйте `python run.py --run-all --kind school` или `--kind garden`. Каждый результат сохраняется в локальную SQLite-базу; ошибка одного сайта не останавливает проверку остальных.

Вместо ручных команд можно из папки проекта запустить `./start-linux.sh`: скрипт создаст окружение, установит зависимости при первом запуске и откроет приложение.

На Debian/Ubuntu при создании окружения может понадобиться системный пакет `python3-venv`.

## Подключение DeepSeek API

Без ИИ работают все правила, реестр, история и отчёты. Для подключения DeepSeek создай API-ключ в [личном кабинете DeepSeek](https://platform.deepseek.com/api_keys), затем скопируй `.env.example` в `.env` и заполни:

```dotenv
AI_PROVIDER=deepseek
DEEPSEEK_API_KEY=вставь_сюда_свой_ключ
DEEPSEEK_MODEL=deepseek-flash
```

Можно настроить провайдера прямо в приложении: открой вкладку «ИИ-анализ» → «Настроить ИИ». Алиса AI выбрана по умолчанию; введи API-ключ и ID каталога Yandex Cloud. При необходимости можно выбрать другого провайдера. Ключ хранится только в локальном `.env`; поле ввода скрывает символы, сохранённый ключ не показывается повторно, его можно удалить в настройках. Файл `.env` исключён из Git и получает права доступа только для владельца на Linux.

Не добавляй ключ в Git или исходный код. Запросы идут на официальный HTTPS endpoint `https://api.deepseek.com/chat/completions`; таймауты и ошибки авторизации/лимитов показываются в приложении.

Для Алисы откройте «ИИ-анализ → Настроить ИИ → Алиса AI (Yandex Cloud)».
Введите API-ключ и ID каталога из [Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/quickstart/),
сохраните и нажмите «Проверить подключение». Можно задать те же параметры в локальном `.env`:

```dotenv
AI_PROVIDER=alice
YANDEX_API_KEY=
YANDEX_FOLDER_ID=
```

При аудите Алиса получает выдержки из выборки страниц, встроенный чек-лист ТЗ и результаты правил.
Смысловые замечания видны во вкладке «ИИ-анализ» и HTML-отчёте как подсказки для ручной сверки.
Один запуск проверки учреждения делает один запрос к модели. При ошибке API отчёт по правилам сохраняется.
Запросы к Алисе могут расходовать баланс Yandex Cloud. Ключ из `.env` не публикуйте.
Используется официальная модель `aliceai-llm` через Responses API. Если Yandex Cloud возвращает HTTP 403,
сверьте ID каталога с каталогом сервисного аккаунта. Для Responses API сервисному аккаунту нужна роль `ai.languageModels.user`, а ключу — область действия `yc.ai.foundationModels.execute`.
Подробности в [документации по доступу к API](https://aistudio.yandex.ru/ru/docs/ai-studio/api-ref/authentication).
При HTTP 400 приложение показывает имя отклонённого параметра и ID запроса, если сервис их вернул.
Проверка подключения отправляет короткий текст. При аудите модель получает инструкцию вернуть JSON,
который приложение проверяет перед добавлением подсказок в отчёт.

Также доступны Gemini, GigaChat и локальная Ollama. Для Gemini используйте `GEMINI_API_KEY`,
для GigaChat — `GIGACHAT_CREDENTIALS`, для Ollama — `OLLAMA_URL` и `OLLAMA_MODEL`.

Локальный Ollama:
```dotenv
AI_PROVIDER=ollama
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_MODEL=имя-установленной-модели
```

GigaChat:
```dotenv
AI_PROVIDER=gigachat
GIGACHAT_CREDENTIALS=ваш-ключ-авторизации
GIGACHAT_MODEL=GigaChat
GIGACHAT_SCOPE=GIGACHAT_API_PERS
```

Кнопка «Проверить подключение ИИ» выполняет короткий запрос к выбранной модели. Gemini API использует заголовок x-goog-api-key и endpoint generateContent. Для фактчекинга выберите учреждение, нажмите «Источники фактчекинга» и укажите до пяти URL независимых публикаций. ИИ формирует гипотезы со ссылками; специалист должен подтвердить или отклонить их.

## Данные

База создаётся автоматически в `data/gosweb_audit.sqlite3`. Реестр загружается из `data/organizations.json`. Повторное открытие приложения не удаляет историю и не дублирует учреждения.

## Важные ограничения

1. Это самостоятельная версия приложения. Ветка `education-audit` и код веб-приложения не изменяются.
2. Краулер получает статический HTML. Содержимое, которое сайт рисует только JavaScript, может не попасть в выборку.
3. Даты используются только тогда, когда их можно однозначно связать с публикацией или мероприятием. Если данных не хватает, приложение пишет «Нужна ручная проверка», а не выдумывает нарушение.
4. Лимиты обхода означают, что результат является выборочной проверкой, если в отчёте указано обратное.
5. ИИ-анализ необязателен и требует пользовательской настройки одного из поддерживаемых провайдеров. Если выбран эталон и для него есть сохранённый отчёт, модель получает ограниченную выборку страниц эталона и сравнивает её с проверяемым сайтом. Фактчекинг ограничен внешними URL, которые специалист сам задаёт для учреждения; универсального веб-поиска нет. Подсказки модели не считаются доказанными нарушениями.
6. Сравнение с эталоном пока сопоставляет названия найденных файлов, а не проверяет полный нормативный перечень документов. Визуальное качество баннеров и фотографий требует ручного просмотра.
7. Для регулярных проверок предусмотрен пакетный режим `--run-all`. На Linux его можно запускать через cron, а в Windows — через Планировщик заданий. Расписание задаёт владелец установки; приложение не создаёт системные задания автоматически.

## Скорость проверки

Режим «Быстро» ограничивает обход 30 страницами и 6 документами на сайт, использует тайм-аут 6 секунд и короткую паузу между запросами. «Баланс» — 60 страниц; «Глубоко» — 120. Более быстрый режим может пропустить материалы, поэтому отчёт сохраняет отметку об ограниченном обходе. Gemini запускается один раз на учреждение и может добавить время ожидания ответа API.

## Регулярный запуск в Linux

После установки зависимостей создайте каталог `logs` и добавьте задание в `crontab -e`, заменив путь на фактический:

```cron
0 8 * * 1 cd /home/user/min-cifr/desktop-app && .venv/bin/python run.py --run-all >> logs/weekly-audit.log 2>&1
```

Задание запускает проверку еженедельно по понедельникам в 08:00 по локальному времени машины. Для проверки только школ добавьте `--kind school`, для детских садов — `--kind garden`. Планировщик запускает проверку без окна. Выбранная локальная Ollama должна быть запущена отдельно; при её недоступности встроенные правила и отчёты продолжают работать без ИИ.

## Текущая архитектура

- `edu_audit/crawler.py` — безопасная загрузка и извлечение содержания.
- `edu_audit/rules.py` — проверяемые правила ТЗ.
- `edu_audit/storage.py` — SQLite и история.
- `edu_audit/service.py` — полный цикл аудита.
- `edu_audit/exporters.py` — HTML/CSV-отчёты.
- `edu_audit/gui.py` — графический интерфейс.
- `tests/` — модульные тесты.


## Правила проверки

Требования кейса встроены в программу. Загружать ТЗ не нужно. Вкладка «Правила проверки» объясняет проверяемые разделы и ограничения. Старые импортированные документы не добавляются к новым проверкам из интерфейса.

Кнопки проверки находятся в реестре, экспорт отдельного отчёта — в результатах, общая сводка учреждений — в истории. Сводка показывает замечания и ручные проверки без процентного рейтинга.
