# Проверка отдельной версии с SQLite

Дата: 7 ноября 2026 года.

## Перенос и сохранение данных

Оригинал `education-audit` с MySQL не изменён. Создан отдельный проект `education-audit-linux`. В SQLite перенесены все четыре таблицы из существующей MySQL:

- organizations: 87;
- runs: 8;
- pages: 170;
- results: 165.

Сравнены все значения всех колонок, включая ID, даты, JSON, настройки, доказательства и ручные решения. Совпадение подтверждено. `PRAGMA integrity_check` вернул `ok`, `PRAGMA foreign_key_check` не нашёл нарушений. Источник читался транзакцией без изменений. Учётные данные MySQL и ключи ИИ не копировались в новый проект.

## Автотесты

43 теста прошли. Сохранены прежние тесты правил и GigaChat, добавлены проверки файловой SQLite:

- сохранение русского текста, длинных текстов и JSON после переподключения;
- внешние ключи и WAL;
- конкурентное добавление в очередь без дублирования;
- блокировка второго экземпляра приложения с той же базой;
- первый запуск без .env, .env.example и settings.example;
- повторный запуск без дублирования реестра;
- запуск при заблокированном импорте pymysql;
- согласованная резервная копия работающей SQLite;
- независимость пути базы от текущей папки терминала.

В этом окружении pytest использовал отдельную временную папку внутри work, поскольку системная Temp ограничена правами.

## Живая проверка

На отдельной копии SQLite выполнены: /health → `database: sqlite`, реестр, история, старый отчёт, сравнение, страница ИИ. Через веб-форму с CSRF поставлен в очередь реальный сайт. Обход завершён: 4 страницы и 22 результата правил. Проверены отчёт и CSV/JSON. После перезапуска новый отчёт снова открывается. Тестовый запуск №9 находится в отдельной базе work и не включён в готовый архив; пользовательская база сохраняет исходные 8 запусков.

Дополнительно проверены SQLite SQL-схема/реестр и состав архивов. Исходные файлы MySQL-версии сверены с исходным списком SHA-256.

## Пределы проверки

Функциональная проверка выполнялась на Windows с Python 3.14 и встроенной SQLite, а не на ядре Linux. Linux/WSL в этой среде не установлен. Поэтому фактический запуск на вашем Linux пока не подтверждён. Linux-скрипт использует обычные POSIX sh-команды и Python; системный сервер базы, Docker и sudo из пути запуска исключены.

API-ключ GigaChat не поставляется. Истинный вызов облачной модели без пользовательского ключа не выполнялся; API-поведение покрыто тестами с имитацией ответов. Ограничения статического краулера остались прежними.
