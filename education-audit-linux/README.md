# Контроль сайтов образования — версия Linux с SQLite

Отдельная копия приложения. Для базы используется **SQLite — обычный файл**, встроенная поддержка которого есть в Python. MySQL Server, MariaDB, Docker, sudo, логин и пароль базы не нужны. Исходная версия с MySQL остаётся отдельным проектом.

## Запуск на Linux

1. Распакуйте архив **в новую папку** `education-audit-linux` в вашем домашнем каталоге. Не накладывайте её на старую версию.
2. Откройте эту папку в терминале.
3. Выполните:

```sh
sh start-linux.sh
```

Скрипт создаёт своё Python-окружение, при необходимости устанавливает библиотеки и запускает приложение. Во время первой установки библиотек нужен интернет и Python 3.11+ с модулем venv/pip. Повторный запуск при установленных зависимостях не требует установки пакетов. Краулеру и облачному ИИ интернет нужен для обращения к сайтам.

После строки `Serving on http://127.0.0.1:8000` откройте **http://127.0.0.1:8000** на том же компьютере. Скрипт также пытается открыть браузер автоматически. Терминал оставляйте открытым. Остановка — Ctrl+C. Пока приложение выключено, проверки по расписанию не выполняются.

### Если библиотеки уже стоят в старом проекте

На вашем Linux уже создавалось окружение старой версии. Если две папки находятся рядом, из **новой** папки можно запустить приложение сразу:

```sh
../education-audit/.venv/bin/python run.py
```

Так используются уже установленные библиотеки, но код, настройки и SQLite-база берутся из новой папки. Python-модуль sqlite3 входит в обычную установку Python. Если старый проект расположен иначе, укажите полный путь к его `.venv/bin/python` и затем `run.py`.

После настройки собственного окружения для повтора достаточно:

```sh
.venv/bin/python run.py
```

Если команда сообщает, что экземпляр уже запущен, откройте его вкладку браузера. Не запускайте два рабочих процесса с одной базой.

## Где находится база

`data/education_audit.sqlite3` — все учреждения, история, страницы, результаты, решения специалиста, выбранные эталоны и расписания. Четыре таблицы сохранили прежние названия и связи:

- `organizations` — учреждения и настройки мониторинга;
- `runs` — очередь и история запусков;
- `pages` — извлечённые тексты и источники;
- `results` — результаты, доказательства и ручные решения.

При первом запуске файл, если отсутствует, и таблицы создаются автоматически. В пустую базу добавляются 87 учреждений из JSON. Повторный запуск не удаляет данные и не создаёт дубликаты реестра.

В готовом архиве уже находится копия ваших данных: 87 учреждений, 8 запусков, 170 страниц и 165 результатов. Перенос проверен по каждому полю. Архив исходников для GitHub, напротив, не включает историю и SQLite-файл: база создаётся при запуске.

SQLite можно открыть в DB Browser for SQLite или другом редакторе SQLite. MySQL Workbench не предназначен для этой базы. Переход на SQLite сохраняет функции приложения, но не делает её серверной MySQL: для многопользовательского внедрения с большими объёмами записи потребуется отдельное решение.

### Резервное копирование

Надёжная копия даже при работающем приложении:

```sh
.venv/bin/python tools/backup_database.py backups/education-backup.sqlite3
```

Команда не перезаписывает существующий файл. Для восстановления остановите приложение, сохраните прежнюю базу отдельно и задайте путь к восстановленной копии через `DATABASE_PATH` в `.env`. Если копируете файлы вручную, сначала штатно остановите приложение: SQLite в режиме WAL может использовать соседние файлы `-wal` и `-shm`.

## Настройки

Файл `.env` создаётся автоматически, ничего вводить для подключения к базе не надо. Образец с обычным именем — `settings.example`, поэтому пропуск скрытых файлов браузером GitHub не ломает первый запуск. Пример:

```dotenv
DATABASE_PATH=data/education_audit.sqlite3
HOST=127.0.0.1
PORT=8000
```

Секретный `SECRET_KEY` генерируется автоматически. Его не публикуйте. Прежние `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD` для этой версии не используются.

Если порт 8000 занят, измените `PORT=8001` и откройте http://127.0.0.1:8001. Путь базы всегда считается относительно папки проекта, независимо от того, из какой папки вызван Python.

## Что осталось работать

Реестр школ, детских садов, колледжей и техникумов; обход сайтов с учётом robots.txt; проверки новостей, разделов, контактов и доступности документов; текстовые заглушки; отчёты с источниками, приоритетами и рекомендациями; CSV и JSON; печать/PDF через браузер; история; решения специалиста; сравнение учреждений и эталоны; очередь; расписание; подключение GigaChat и локального Ollama.

Сохраняются ограничения прежней версии: статический HTML без выполнения JavaScript; лимиты обхода; PDF без текстового слоя требует OCR; содержание Word/Excel-файлов не анализируется; размеры/содержание фотографий не проверяются; неопределённые выводы требуют сверки. Полноценный поиск подтверждений по всему интернету не реализован.

## GigaChat

Для запуска приложения ключ не нужен. Если нужен ИИ, откройте проект GigaChat API в кабинете Сбера и проверьте доступную квоту. Получите Authorization key, затем:

```sh
.venv/bin/python configure_gigachat.py
```

Скрытый ввод сохраняет ключ только в `.env`. Либо вручную заполните `GIGACHAT_CREDENTIALS` и `AI_PROVIDER=gigachat`. Перезапустите приложение, откройте «Подключение ИИ» и проверьте соединение. Для сертификатов поддержан `GIGACHAT_CA_BUNDLE`; проверка TLS остаётся включённой. Подсказки появятся в **новых** проверках. В готовый архив API-ключ не включён, облачная генерация без него не заявляется работающей.

## Однократный перенос из другой MySQL

Это необязательный инструмент, обычному Linux-запуску он не нужен. Если требуется другая история из MySQL, на компьютере с доступом к старой базе установите дополнительные зависимости:

```sh
python -m pip install -r requirements-migration.txt
python tools/migrate_mysql.py --source-env /path/to/old/.env --destination /path/to/new-copy.sqlite3
```

Источник читается без изменений. Новый файл должен отсутствовать; существующая база не перезаписывается. Переносятся все четыре таблицы с ID, датами, JSON и ручными решениями. После переноса проверяются совпадение данных, целостность и внешние ключи. Укажите полученный файл в `DATABASE_PATH` или перенесите его на Linux после остановки приложения.

## Тесты

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Отдельно проверены SQLite на диске, русский текст, связи, конкурентная очередь, блокировка второго рабочего процесса, запуск без скрытых шаблонов, резервная копия и прежние проверки. Фактические результаты и ограничения среды описаны в `VERIFICATION.md`.

## Публикация исходников

`python tools/package.py --source-only` создаёт отдельный архив для GitHub без `.env`, виртуального окружения, базы и истории. Готовая пользовательская сборка создаётся `python tools/package.py`. Не загружайте на GitHub `.env` с ключами.

Интерфейс по умолчанию доступен только на своём компьютере. Для публикации в интернете по-прежнему нужны авторизация, HTTPS и сетевые ограничения.
